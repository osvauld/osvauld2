# W3 — Shell, accounts, store, tabs, MCP (2026-08-04)

W2's app layer runs, but the app is an island: its state lives in Lua tables that vanish on
restart, it loads from a hardcoded path, and nothing outside the process can see or touch it.
W3 gives the app layer a **world** — an account that owns a database, workspaces holding typed
files, a Loro doc per file that persists, tabs hosting several apps at once, and a socket the
agent talks to. This is the **M1 exit test** (the agent authors a working app over MCP), pulled
from W5 to W3.

Companion: `runtime-3month-plan.md` (the *when*), `runtime-rebuild-plan.md` (the *what/why*),
`loro-notes.md` (Loro's actual mechanics, read out of the source — §3 leans on it).
Reference-only: `sthalam/` (the old egui shell — its screens, `bridge.rs` and `seed_item_state`
are the flow to copy, never the code) and `osvauld-mcp/` (ports in shape, shrinks in surface).

**Calendar.** Two days went to finishing kanban. W3 runs **Wed 8/5 → Fri 8/14, 8 working days** —
it borrows three from W4. Original W3 (hot reload + error cards) and W4 (types gate + harness)
merge into one DX week after this; **W6's float is what pays for it**, which is exactly the job
the 3-month plan gave it. The trade is deliberate rather than forced: hot reload and error cards
are worth far more *after* apps are files in a store and MCP is the thing writing them — reloading
a hardcoded path was always the weaker version of that week.

## Goal
An account you create in the shell owns a redb store. Workspaces and typed items live in it.
Opening an `.app` item loads its `main.lua` and its Loro state, runs it in a tab, and persists
every mutation. Several apps stay open at once. An MCP client on a UDS can list/create/read/write
all of it, plus inspect and drive the running app — with the window repainting the moment it does.

## 0. External wakeup — the seam everything else needs  (LOAD-BEARING)
Theory: the runtime is `ControlFlow::Wait` + on-demand paint, and `EventLoop::new()` has no
user-event channel — **nothing outside winit can reach the app today.** Two W3 features are
blocked on this and both fail *silently* without it: the Argon2 worker (signup/unlock hash off
the UI thread; when the worker finishes, nobody repaints) and the bridge thread (an MCP write
must land *and* repaint). sthalam never needed this because egui repaints continuously; we do.
Build it first — it's ~30 lines and every section below assumes it.

**Attempted and reverted 2026-08-05** (written without pairing; backed out at the user's request —
not because it was wrong). It compiled and the whole workspace built. What it took, for whoever
does it properly: `pub use winit::event_loop::{EventLoopClosed, EventLoopProxy}`; `type Msg:
Clone + Send + 'static` (all existing `Msg` types already qualify — `LuaMsg`, shell2's
`Login`/`Todo` are plain data); `impl<A: App> ApplicationHandler<A::Msg> for Runner<A>` (winit
0.30's trait is `ApplicationHandler<T: 'static = ()>`); a `user_event` arm doing `update` +
`redraw`; and `run_with(build: impl FnOnce(EventLoopProxy<A::Msg>) -> A)` with `run` as sugar.
A demo (worker thread ticking once a second) **did** drive the window with no input — `update` →
`view` in the trace — but delivery looked intermittent across runs and was never diagnosed. Treat
"every tick lands, not just the first" as part of the done-when.

**Decision: the external event type is `App::Msg` itself.** No second vocabulary, no
`on_user_event` trait method — a worker thread and a click are the same kind of input, which is
the same "one node vocabulary" discipline applied to events.
- [ ] `EventLoop::<A::Msg>::with_user_event()`; bound becomes `A::Msg: Clone + Send + 'static`
- [ ] `run_with<A: App>(build: impl FnOnce(EventLoopProxy<A::Msg>) -> A)` — the app needs the
      proxy at construction to hand to its workers; keep `run(app)` as sugar over it
- [ ] `ApplicationHandler::user_event` → `self.app.update(msg); self.redraw()`
- [ ] **Done when:** a thread that sleeps 2s then sends a `Msg` visibly changes the window with
      no mouse movement and no key press.

## 2a. App upload — sources as a Loro doc  (decided 2026-08-12)
Theory: **publish/update is the forcing argument.** An app update ships as a Loro update blob that
merges into the local copy — a plain-bytes key can't receive one. So sources are Loro-native from
birth, not converted later.

**Shape.** Source and state are never one doc: a **source doc** sealed at `ws/<ws>/item/<id>/src`
(host and MCP write it; Lua never sees it), and the app's **state docs** at `…/doc/<name>` — plural,
name-keyed, opened on demand by Lua (§3 revised this from a single `…/state` key on 2026-08-27).
Code and data don't share a container.
- inside the source doc: a `files` LoroMap, path string → LoroText per file. Folder structure is
  read off the `/`s — the path *is* the identity, the rule `item.rs` already states for the file
  keys it replaces. **Map, not LoroTree:** tree buys folder renames and costs the
  delete-hides-subtrees and handle-re-resolution scars, and you'd rebuild path strings anyway for
  error messages and `require`.
- `manifest.osv` is just another entry. Not parsed beyond a string-match for `app "<name>"`; the
  rendered name stays `WorkspaceItem.name`, one source of truth. The old `.osv` grammar (roles,
  `ui_app`, allow lists) is what the auth rewrite replaces — no parser is worth writing against it.
- **no temp files, ever.** `lua.load(src).set_name("main.lua")` puts the file name in errors and
  tracebacks straight from the doc. Multi-file later: `require("lib.state")` → `files["lib/state.lua"]`
  → same `set_name`, plus a `package.loaded`-style cache. W3 *stores* multi-file faithfully and
  *runs* `main.lua` only.

**vault.**
- [ ] one private sealed-blob helper (`encrypt_for` / `decrypt_sealed`, as `meta` already does);
      `put_src`/`get_src`/`put_doc`/`get_doc` are four one-line wrappers over it
- [ ] **`put_doc`/`get_doc` gain the sealing `put_state`/`get_state` were always meant to have** —
      do it now, while dev stores are throwaway (`OSVAULD_DATA_DIR`) and there is nothing to migrate
- [ ] `doc_key(ws, item, name)` → `ws/<ws>/item/<id>/doc/<name>` replaces `state_key` (§3). Nothing
      released, so this is a rename, not a migration — but do it before kanban writes real data
- [ ] `create_item` stops seeding `manifest.osv` into a `files/<path>` key; that key family retires
      for apps and seeding moves to the shell, which owns Loro (sthalam's `seed_item_state` reborn).
      Stale comments in `vault/src/item.rs` and `vault/src/lib.rs` still describe block_doc seeding
- [ ] Loro stays out of vault; `shell2` gains the `loro` dep

**Upload flow** — synchronous inside `update`: no worker, no proxy round-trip, and **no overlay or
name input** (the name comes from the manifest or the folder), so the button goes straight to the
picker. This is the one screen action that *doesn't* copy the workspace-create pattern; revisit only
if reading a folder ever gets slow enough to feel.
- [ ] pick a folder → read `*.lua` + `*.osv`, paths relative to the root, `/`-separated → reject if
      there's no root `main.lua` (the entry-point contract)
- [ ] name from `app "<name>"`, else the folder name → `create_item` → build doc → export snapshot →
      `put_src`
- [ ] **errors get rendered** — folder missing, no `main.lua`, non-UTF-8 file. First real use of the
      `error` slot both screens already stash and neither shows
- [ ] re-upload is **create-only** this week. When update lands: per-file compare, write only what
      changed, delete what's gone. A wholesale rewrite makes every file's history "delete all,
      insert all" — huge blobs that steamroll local edits on merge. In-file diff splicing is
      publish-era, not this.

**File picker — decision: sync `rfd::FileDialog::pick_folder()` on the UI thread, every platform,
no branch.** The dialog blocks winit's loop while it's open, and that costs us nothing worth paying
for: every backend draws the dialog outside our loop (a separate portal process on Linux; a modal
that pumps its own run loop on macOS and Windows), so the *dialog* stays responsive either way —
only the window behind it is frozen, and there's nothing to look at back there during a folder pick.
A branch buys a live window behind a modal. Not worth it now.

Worth knowing before the mac port, because it's what a branch would have to respect: **`NSOpenPanel`
is AppKit and must run on the main thread**, which on macOS *is* winit's event loop thread — so the
usual "spawn a worker and block" escape hatch has nowhere to go there. Main-thread-everywhere is
therefore the choice that needs no port; the branch only becomes necessary if we ever want the
window live behind the dialog, and on macOS that means a non-modal presentation with a completion
handler (call returns immediately, path arrives in the callback, then over the proxy). Second
macOS-only wrinkle for later: under App Sandbox **the picker is the permission grant** — a pasted
path grants nothing, a user-picked folder does, and keeping that access across launches needs a
security-scoped bookmark. That makes the picker the real path on macOS eventually, not merely the
nicer one.
- [ ] **Done when:** point at a folder → the app appears in the workspace → clicking it runs its
      `main.lua` → it's still there after a restart.

## 3. Loro — the app's state store  (the W2 §5 debt)
Theory: this is w2.md §5, cut from W2 and now due. `app_host` already declares `loro` and never
calls it; kanban keeps cards in Lua tables. Single-writer this week — but the *read* path is
designed for three writers (Lua, the MCP bridge, peers later), because retrofitting that is a
rewrite and doing it now is free. `app_engine/src/script/crdt.rs` is **reference only**; nothing
is ported wholesale.

**Decision (2026-08-27) — reads and writes are different paths.** Reads are plain Lua tables that
Rust pushes when the document changes. Writes are explicit CRDT calls through userdata. One
direction is cheap and local, the other goes to the network, and the API makes which is which
visible instead of hiding it behind a uniform accessor.

**Why not read-through userdata** (the shape `crdt.rs` uses, where `c.title` resolves into Loro on
every access): `runtime/src/lib.rs:729` requests a repaint on *every* `CursorMoved` — hover has to
follow the pointer — so `view()` runs at pointer rate, not once per interaction. Read-through, one
`c.title` is a metamethod hop + a container re-resolve + a `LoroValue` clone + a fresh Lua string.
A 200-card board reading 5 fields each is ~1000 of each **per repaint**; a mouse sweep at 120Hz is
~120k string allocations a second to redraw a hover tint. The mirror pays that only when the
document actually changes — break-even is 2 repaints per write, and the real ratio is ~100:1.

It is also **less** code, not more: the entire read half of `crdt.rs` (`LuaList::get`, `LuaMap`'s
`Index` metamethod, the `MapAt` enum, `LuaText::get`) never gets written. The write half is needed
either way.

**Storage — name-keyed, item-scoped.** `ws/<ws>/item/<id>/doc/<name>`, sealed like every other key;
`get_doc`/`put_doc` replace `get_state`/`put_state`. Item-scoped rather than workspace-scoped costs
nothing today and avoids baking in a flat namespace where two apps both want `"settings"`. An app
may open many docs; the set is dynamic, discovered by what Lua asks for.

**Lua surface.** `doc:open(name)` returns the mirror **table** for that doc, with a metatable
carrying the write methods. No implicit default doc — `doc:open` always, so a second doc is never
a special case.
```lua
local board = doc:open("board")            -- lazy + idempotent; per-frame calls are a hash lookup
board.cards[1].title                       -- read: plain table index. no FFI, no allocation
board:add("cards", { title = "x" })        -- write: explicit CRDT op
```
Returning the mirror itself (rather than a handle beside a `state` global) means reads never pay a
metamethod at all, and the table's identity is stable — an app may hoist `local board` into a
module local. That stability is what forces the rebuild to **patch in place** (clear keys, refill)
rather than swap in a fresh table. *Hazard:* a doc whose top-level container is named `add`/`list`/
`text` shadows a method. Reserve the method names and say so in the app docs.
- [ ] `doc:open(name)` — resolve from vault (or `LoroDoc::new()`), subscribe, build mirror, return
      it; idempotent on re-open. Populate the mirror **during** `open`, not on the next frame — an
      app calling `doc:open` inside `view()` must be able to read it in that same `view()`
- [ ] writes: `:add(list, fields)`, `:remove(list, id)`, `:move(list, from, to)`, `:set(map, k, v)`,
      `:text(name, s)`. **Address by stable id, never by mirror index** — the mirror is positional
      and a concurrent insert shifts it
- [ ] `:add` stamps a stable id at birth (app-supplied string id wins; reject dupes) — the same id
      is the retained-state key from w2.md §3
- [ ] the old scar still holds on the write side: containers hold a **name**, never a handle, and
      re-resolve on every call. `LoroDoc` by value throughout — `clone` is a refcount bump
      (`loro/src/lib.rs:114-122`), so there is no `Rc<LoroDoc>` anywhere
- [ ] scalar coercion both ways (bool/i64/f64/string ↔ Lua); the mirror is built from
      `doc.get_deep_value()` (`loro/src/lib.rs:937`), so nested containers come through as nested
      Lua tables for free — the `nil` fallback the old bindings had is not needed

**Change detection.** One `subscribe_root` per doc, created in `doc:open`. *Which* doc changed is
answered by which closure fired — there is no dispatch. The subscriber does the **minimum** and
touches nothing else:
```rust
struct DocEntry {
    doc: LoroDoc, version: Arc<AtomicU64>, mirrored: u64, saved: u64, _sub: Subscription,
}
```
- [ ] **the subscriber must never enter Lua.** It fires inside `commit()`, which is inside a Rust
      fn that Lua called; re-entering there is one step from a `BorrowError` on
      `LuaApp.handlers` (`RefCell<Vec<Function>>`) or on the borrowed userdata — intermittent, and
      only under load. It bumps a counter and pokes the proxy, nothing more
- [ ] `Subscriber` is `Arc<dyn Fn + Send + Sync>` (`loro/src/event.rs:26`), so the counter is
      `Arc<AtomicU64>` — **not** `Rc<Cell<_>>`. Same shape `sandboxed_vm` already uses for `fires`
- [ ] a **monotonic counter with two watermarks**, not a `dirty` flag: the mirror rebuild and the
      vault write are separate consumers, and whichever called `.take()` first would starve the
      other. `mirrored` and `saved` advance independently
- [ ] hold the `Subscription` in `DocEntry` — dropping it unsubscribes silently, which presents as
      "MCP writes don't show up", not as an error
- [x] the subscriber also pokes the event loop: an MCP or peer write has no input event behind it,
      so without the poke the doc changes and nothing repaints. This is what §0's wakeup seam was
      built for. Shipped as `app_host::Wake` (`Arc<dyn Fn() + Send + Sync>`) rather than a direct
      `send_event`, because `app_host` cannot name shell2's `Msg`; shell2 builds one from the proxy
      in `waker()` and it sends the payload-free `Msg::DocChanged`. Payload-free on purpose — any
      user event repaints, and `view()` already knows which docs are stale from their counters
- [x] **gate that poke on `ev.triggered_by == EventTriggerKind::Import`** — a `Local` write already
      has an input event behind it and will repaint anyway. The enum is `Local | Import | Checkout`
      and there is **no `Export` variant**: `export()` only fires a `Local` event for ops that were
      still pending (`with_barrier` → `implicit_commit_then_stop`), and since every write here
      `commit()`s immediately, nothing is pending and nothing fires. There is no export/save loop
      to defend against. See `loro-notes.md` §7

**The push happens at one controlled point** — the top of `view()`, before `view_fn` runs. Nothing
is executing in Lua there, so re-entrancy is impossible by construction, and external writes land
in the same place (proxy → `update` → `view`), so one site covers all three writers.
```
click → update() → handler → :add() → commit() → subscriber: version++, proxy poke
      → view():  for each doc, if version > mirrored { patch mirror in place }  → view_fn()
      → shell:   for each doc, if version > saved    { export(Snapshot) → put_doc }
```
- [ ] **W3 ships the whole-doc rebuild** (`get_deep_value()` → recursive `LoroValue` → Lua). Simple
      and unconditionally correct
- [ ] but the subscriber **collects owned changed-container paths from day one** — ~10 lines, and
      it's the one part that is awkward to retrofit, because `DiffEvent<'a>`/`ContainerDiff<'a>` are
      borrowed (`loro/src/event.rs:29,42`) and cannot be stashed for later. Everything downstream is
      just what `view()` does with the list:
      ```rust
      let changed: Vec<(Vec<Index>, ContainerID)> = ev.events.iter()
          .map(|c| (c.path.iter().map(|(_, i)| i.clone()).collect(), c.target.clone())).collect();
      ```
- [ ] **next tier, when a profile asks for it:** per-container invalidation — re-derive
      `get_deep_value()` on *just* the changed containers and splice at their path. ~60 lines, takes
      the rebuild from O(document) to O(changed container), i.e. one card instead of the whole board
- [ ] **not planned:** true delta application (`Diff::List`'s Retain/Delete/Insert, `MapDelta`,
      `TextDelta`). It is several hundred lines for the last few percent — the expensive thing was
      never the sequence arithmetic, it was marshalling every string in the document. It also
      carries real edges (`is_move` on every MovableList move, so every kanban cross-column drag;
      `is_unknown` containers needing a full-rebuild fallback; `Insert.insert` carrying
      `ValueOrContainer`, so a nested card needs deep-valuing inside the callback anyway). And text
      buys nothing at any tier: a `LoroText` mirrors to a plain Lua string, so any edit replaces the
      whole string however precise the delta was

**Persistence.** After `update`, for each doc where `version > saved`, export a snapshot
(`ExportMode::Snapshot`) → `put_doc`. Whole-snapshot per write is fine at this scale;
`ExportMode::Updates(from)` and debouncing are optimizations, not this week's problem.

**No query API this week, and the mirror is why.** Once reads are plain tables, filtering 200 cards
is an ordinary Lua loop — no FFI, no allocation — so `:where` earns nothing. A query surface only
matters again at table scale, and that is the existing opaque-handle path (`data.sql` →
`table_query`, "bulk rows never cross into Lua"), which is World B and a separate piece of scope.
- [ ] port the kanban off Lua tables onto `doc:open("board")` — `board.columns` / `board.cards` for
      reads, `board:add`/`:move`/`:set` for writes. The cross-column drop becomes `:move` + a field
      set — the exact case §5 of w2.md was written for.
      **Port `shell2/src/kanban/main.lua`** (584 lines — the typed-drag rewrite this section used to
      call "kanban2"; `main3.lua` is the older simpler one, `test.lua` is the layout reference).
      It fills the viewport, has a scrolling card area with a pinned composer, typed drags
      (`drag.kind` = `"card"`/`"col"`) so column reordering and card drops share one `on_drop`,
      floating ghosts at the root (out of every scroll clip), always-present fade-driven drop
      guides — verified to keep the board's layout tree byte-identical while dragging, so nothing
      reflows — plus `ui.state` for per-instance UI state. Most of the bug list below is already
      fixed there; keep it as the reference and retire the others.

**Deferred, deliberately** (none of it blocks the above, and each is a separate week-sized piece):
the workspace index doc (`name → doc_id`, so docs get identity independent of their label), aliases
and bindings, manifest-declared doc slots, permits and cross-app access, kunki as the merge

- [ ] clear the open `kanban.lua` bugs while porting (all found in the W2 debug pass, all still

## 4. Tabs — several apps open at once
Theory: `runtime::run` drives one `App`; multiplexing is the **shell's** job, not the runtime's.
**One running instance per item, always** (decided 2026-08-24) — a tab is a *reference* to a
running app, not a container that owns one. `Shell` holds `apps: HashMap<Arc<str>, LuaApp<Msg>>`
keyed by `item_id`. Opening an already-open item focuses its existing entry — no second VM, no
second doc handle. This is also what a future split pane is: another reference into the same
`apps` entry, correctly sharing state (same caret, same scroll) because it's the same instance,
not a copy — so it needs no design now.

**Home is a tab, not a separate screen mode** (decided 2026-08-24, matches sthalam's proven
shape — `sthalam/src/shell/mod.rs`: `enum Tab { Home, Workspace{..}, Open{..} }` inside one
`DockState<Tab>`). `tabs: Vec<Tab>` where `enum Tab { Home, App(Arc<str>) }`, `tabs[0] = Tab::Home`
always present, never closed. `Home` carries no state of its own — it renders whatever `Screen`
(`Spaces`/`Items`) is currently active; opening an app never touches `screen`, so "going home" is
just refocusing tab 0, nothing rebuilt, nothing lost. The outer `Screen::{Signup,Mnemonic,Login}`
gate stays exactly as it is — sthalam draws the same line: no dock exists before unlock.
**Not this week:** real docking (egui_dock's `DockState` is a full split-tree — drag-to-dock,
resizable panes). The `Tab` enum above doesn't block building that later; it's a separate,
week-sized piece of scope, not a rename.

`El::map` doesn't exist and isn't getting written (decided 2026-08-21): `app_host` is generic
over the message type `M` instead — `LuaApp<M>` threads a `to_msg: Rc<dyn Fn(LuaMsg) -> M>`
through the walk, so every callback/input/drag site stamps its return address as it's minted.
Zero extra tree traversal per frame. Landed in `app_host`. `Msg::Tab(Arc<str>, LuaMsg)` — the
`Arc<str>` (not `String`) matters because `to_msg` fires per callback per frame, not once per
tab; a `String` there is a per-frame allocation per handler.

**Hazard — name it now:** the runtime's retained store is keyed by `Id` **alone**. Two open apps
that both name a field `"draft"` share one `Field`: same caret, same text. The walk must
**namespace every id with the item id** (`"<item_id>:<id>"`) before it reaches `El::id`. Same for
scroll offsets and animation progress. This bites within a minute of two apps being open, and it
presents as a runtime bug rather than a key collision — an easy day to lose.
- [ ] `apps: HashMap<Arc<str>, LuaApp<Msg>>` on `Shell`; `tabs: Vec<Tab>` (`Tab::Home` at index 0,
      `Tab::App(Arc<str>)` after); `focused: usize`; `Msg::Tab(Arc<str>, LuaMsg)`
- [ ] `open_tab(item)`: insert into `apps` if absent (read `vault.get_src`, import into a fresh
      `LoroDoc`, `LuaApp::open`), then focus its existing `Tab::App` entry or push+focus a new one
- [ ] tab strip: `Tab::Home` renders `⌂`/label fixed at index 0; click to switch; **close tears
      down** a `Tab::App` — removed from both `tabs` and `apps`, VM and doc handle dropped.
      Reopening re-imports the doc from vault and re-evals `main.lua`; the done-when below is
      about *switching*, not reopening after a close, so this stays cheap where it needs to be
- [ ] id namespacing in `app_host`'s walk, prefix set once at open, keyed on `item_id`
- [ ] only the focused tab's app runs `view()`; backgrounded entries in `apps` keep their doc + VM
      alive
- [ ] **Done when:** two apps open, each keeps its own field text and scroll offset, switching is
      instant, and both persist independently.

## 5. bridge2 — one authority, no merge
Theory: sthalam's bridge mutated the vault **on the bridge thread** and shipped a `Refresh`
snapshot for the UI to merge — necessary there because egui's frame loop couldn't be interrupted.
§0 changes the calculus: **the bridge becomes pure transport and the UI thread executes every
request.**

Request arrives on the socket → `proxy.send_event(Msg::Rpc(req, reply_tx))` → the shell handles it
inside `update` (it already owns the vault, the tabs and the live docs) → `Response` back on
`reply_tx` → the bridge writes it to the socket. One writer, so a live doc can never diverge from
its durable snapshot; no `Refresh` enum at all; repaint for free. It is strictly **less** code
than the version it replaces. The cost is that a slow request blocks a frame — true only of
screenshot and SQL, neither of which is in this week.
- [ ] `bridge2` in shell2: `UnixListener` on `$OSVAULD_SOCKET` (default `/tmp/osvauld.sock`), one
      request per connection, 4-byte length prefix — `osvauld_rpc::{read_msg,write_msg}` as-is
- [ ] `Msg::Rpc(Request, Sender<Response>)`; `Shell::update` dispatches and always replies
- [ ] trim `osvauld_rpc::Request` to the live subset and **add `CreateWorkspace`** — the old enum
      never had one (sthalam could only ever list them)
- [ ] W3 surface: `ListWorkspaces`, `CreateWorkspace`, `ListItems`, `CreateItem`, `ListFiles`,
      `ReadFile`, `WriteFile`, `AppDataGet`, `AppDataRowAdd/Set/Remove`, `AppDataSetText`
- [ ] `WriteFile` against an open tab reloads that tab's VM **keeping its doc** — the free half of
      hot reload, earned because the write now comes through the front door
- [ ] **Done when:** `list_workspaces` answers over the socket while the window sits idle, and a
      `write_file` visibly changes the running app without a restart.

## 6. Senses — dump_tree, click, console
Theory: the MCP loop is act → observe → assert, and the observation must be cheaper and more
assertable than pixels.

**Decision:** W3's `dump_tree` serializes the **`El` tree** — tag, id, text, which handlers exist,
a small style summary — **without computed rects**, and `click` targets an **element id, not a
coordinate**. Rects and pixels live in the `Runner`, which an `App` can't reach; buying that
access is a runtime seam not worth this week. Id-addressed clicks are also the better agent
affordance — they don't move when layout changes.
- [ ] `El::to_json()` in runtime (tag, id, text, handler flags, style summary)
- [ ] `El::find_by_id(&self, id) -> Option<&M>`; `Click { id }` → `update(msg.clone())`
- [ ] `DumpTree { ws_id, item_id }` → the tab's current `view()`, serialized
- [ ] console ring buffer: `LuaApp`'s view/handler errors stop being `eprintln!` and become a
      bounded `VecDeque<String>`; `ReadConsole` drains it
- [ ] `ReadState` = `AppDataGet` — the Loro doc as deep JSON
- [ ] **Done when:** create an app over MCP, write its `main.lua`, dump the tree, click a button by
      id, read the state change back — without touching the mouse.

## Deliberately NOT W3 (next weeks)
- error cards + tracebacks + file-watch reload (W4 — §5 gives the reload half for free). The W2
  debug pass already landed most of the *reporting* half in `app_host`: per-element `line` capture
  via `debug.info`, a `Ctx` carrying `path`/`errors`/`dev`, error boundaries in `children()` that
  render a red box in place and keep siblings alive, and key-dumps on leaf failures. What's left
  for W4 is the test suite locking it in, plus these known follow-ups: the boundary leaks mlua's
  `runtime error: ` prefix; the `on_drag`/`on_drop` BINDS use a bare `?` on a missing `id`, so a
  handler on an id-less element reports "error converting Lua nil to String" instead of
  "`on_drop` needs an id"; the path separator is
  inconsistent (`col#root:[2]> [2]`); unknown-tag doesn't record to `errors`; `keys()` quotes key
  names and has unstable ordering. The `dev` flag is declared but not yet gating anything —
  measured cost of the instrumentation is 0.19ms of a 0.92ms frame at 387 elements, so it's a
  scale/principle change, not an urgent one.
- types gate, `ui.d.luau` stubs, `validate_app` (W4); `lua_app::Harness` (W4)
- `screenshot` (needs an offscreen wgpu path — W4/W5)
- per-block `.lua` edits (`read_file_blocks`/`set_file_block_text`) — needs the code_editor splitter
- `.doc` / `.table` / `.canvas` items; account switching + recovery UI
- debounced/incremental persistence; sync, peers, iroh
- **apps off the UI thread** (discussed 2026-08-12, deliberately parked). Today every VM runs on the
  UI thread; the sandbox has no blocking API and `sandboxed_vm`'s interrupt budget kills a runaway
  loop, so the worst case is one slow frame, not a freeze — but a heavy app still drags the window.
  The move, when N visible apps make it pay: each tab's VM + docs own a thread, `LuaMsg` in over a
  channel (it's already plain data — `Call(u32)` etc.), the `El` tree back out, `EventLoopProxy` to
  wake the window. Two costs to price then: the painted tree can lag the VM, so trees and messages
  need generation stamps or a click invokes a stale handler index (handlers are refilled per frame);
  and `El` must be `Send`, which means `Send + Sync` on rust-side `custom` painters (Lua apps don't
  use them — the planned path primitive is a `d`-string, i.e. data). **What keeps the door open is
  already the house rule: messages stay plain data, the VM never leaks into the runtime.**
